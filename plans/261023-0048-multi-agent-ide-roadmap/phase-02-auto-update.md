# Phase 2: Auto-update

## Overview
Signed in-app updates from GitHub Releases (public repo `baopeak/kelpie`), and installers that never fail
on files held by a running daemon. Honest contract: updating stops running processes; agents with resume
support continue their conversation afterwards, shells and agents without resume start fresh — the
dialog says which.

Decisions (user, 2026-10-23): GitHub Releases public; Claude generates the minisign key outside the repo,
the user stores it (GitHub secret + offline backup); the public key is committed. After review: one
**universal** macOS build (Apple Silicon + Intel); releases are created as **drafts** and published by the
user after checking the files.

**Design change (user, 2026-10-23 evening): updates must not affect running sessions.** The app now
starts the daemon from a per-build copy in `<data dir>/daemon/` (`daemon_runtime.rs`), so the
installer replaces the install folder while the daemon and every session keep running; the
installer restarts the app, which reconnects. The older daemon serves its sessions until none runs,
then hands over (`checkDaemonApi` / `handOverIfIdle`), or on *Switch now*. The in-app updater no
longer stops the daemon; the installer hook (`stop-daemon.ps1`) stops only programs directly in
`$INSTDIR` (a 0.1.x daemon). Requirements 1–3 below are superseded where they say the daemon is
stopped for an update; `kelpied stop --wait` stays for the legacy migration and for uninstall.

## Verified against the code (2026-10-23, replaces the earlier draft)
- `kelpied stop` (`main.rs`, `daemon.shutdown {kill_sessions:false}`) already keeps sessions resumable:
  `serve()` returns, the ticker stops, `persist(true)` saves live sessions `alive:true` while their processes still
  run (`saved_sessions`: `alive || interrupted`), the process exits and job objects close; `restore()` marks
  them interrupted. **No new upgrade RPC is needed.** Only the app's "Restart daemon" toast
  (`store.ts` `checkDaemonApi`, `kill_sessions:true`) loses resume.
- There is no daemon version check; only `API_LEVEL` (now 6). `daemon.info` already returns `version` and `pid`.
- The NSIS installer fails on files in use: `kelpied.exe` and every session's `OpenConsole.exe` run from the
  install folder (`%LOCALAPPDATA%\Kelpie`) — the error users see today ("Error opening file for writing … OpenConsole.exe").
- Version source: `Cargo.toml`, `app/package.json`, `tauri.conf.json` (now 0.1.2); `scripts/build-release.sh`
  bumps the patch on every run (another session's change).

## Requirements
1. **Installer safety (fixes today's error)**
   - `kelpied stop --wait [--timeout-ms N]`: graceful stop as today, then wait until that daemon's pid is gone
     (default 15 s; exit 0 when gone, 2 on timeout). Unknown flags stay ignored by older daemons' CLIs.
   - NSIS `NSIS_HOOK_PREINSTALL` (tauri `bundle.windows.nsis.installerHooks`): if `$INSTDIR\kelpied.exe` exists,
     run it with `stop --wait` hidden (`nsExec`), then wait ≤ 3 s more for processes **whose executable is inside
     `$INSTDIR`** (kelpied.exe, OpenConsole.exe, kelpie-stt.exe) and force-stop only those. Never match by name:
     a dev or test daemon elsewhere (or the one hosting an agent session) must survive.
2. **Daemon mismatch after an install**: the app compares daemon `version` with its own (new `version` in
   `platform_info`) as well as `api`. On mismatch the toast's "Restart daemon" uses `kill_sessions:false`
   (sessions come back interrupted and resume).
3. **Updater** (`tauri-plugin-updater` 2.x, Rust side `app/src-tauri/src/updater.rs`):
   - `update_check` → `{version, notes, date} | null`; `update_install` downloads (progress events), stops the
     daemon (`daemon.shutdown {kill_sessions:false}` + wait for its pid), then installs (Windows: installer in
     passive mode; the app exits).
   - Checks: 30 s after start, then every 6 h, only when Settings → System → *Check for updates* is on
     (default on); never while offline errors repeat (back off).
   - UI: status-bar chip "Update {version}"; dialog (lazy) with release notes, the list of working sessions that
     will be interrupted and whether each can resume; **Install now** / **Install when idle** (waits until no
     session is *working*) / **Skip this version**.
   - Endpoint + public key are compile-time config. Test overrides (`KELPIE_UPDATE_ENDPOINT`,
     `KELPIE_UPDATE_PUBKEY`, `KELPIE_UPDATE_DRY_INSTALL`) exist only behind Cargo feature `e2e-updater`, which the
     release build never enables (CI asserts it).
4. **Release pipeline**
   - Key pair generated by `pnpm tauri signer generate` into `%USERPROFILE%\.kelpie-signing\` (never in the repo);
     public key in `tauri.conf.json` `plugins.updater.pubkey`; `bundle.createUpdaterArtifacts: true`.
   - `.github/workflows/release.yml` on tag `v*`: check the tag equals the version in `Cargo.toml`, build Windows
     (NSIS) and macOS (app + dmg) with `TAURI_SIGNING_PRIVATE_KEY(_PASSWORD)` secrets, create the GitHub release,
     upload installers + updater artifacts + `.sig`, and `latest.json` made by `scripts/release/latest_json.py`.
   - `build-release.sh` skips its version bump when `KELPIE_KEEP_VERSION=1` (CI release builds).
5. **Docs**: README Install ("updates itself"), user guide "Updates", architecture (updater + installer hook).

## Implementation Steps
1. `kelpied stop --wait` + unit test of the wait helper; NSIS hook; verify the hook compiles in a bundle build.
2. `platform_info.version`; `checkDaemonApi` compares version too and restarts without killing sessions.
3. Key pair (outside the repo); plugin + config; `updater.rs` commands with the feature-gated overrides.
4. `updater.ts` (schedule, idle gate, skip) + status-bar chip + lazy dialog + setting; vitest for the pure logic.
5. Release workflow + `latest_json.py` + `KELPIE_KEEP_VERSION`.
6. Docs; tell the user the exact `gh secret set` commands (the user runs them).

## Tests
- `cargo test`: wait-for-exit helper; `latest_json.py` on fixtures (run from the e2e script).
- vitest: update scheduling, "install when idle" decision, skipped version.
- e2e `scripts/e2e/updater.py`, isolated daemon only (never the real install):
  1. `kelpied stop --wait` on a daemon with 3 shells → returns after the pid is gone; `sessions.json` lists them alive;
     a new daemon restores them `interrupted`.
  2. With an `e2e-updater` build of the app core (dry install): a local HTTP server serves `latest.json` + a bundle
     signed with a throwaway test key → check finds the update; a bad signature is rejected; dry install stops the
     test daemon and reports success without running an installer.
- Manual (the user, Kelpie closed or in Windows Sandbox): install 0.1.x over a running 0.1.x with sessions open → no
  "file in use" error, sessions resume; then a real in-app update from a published release.

## Perf gate
- No timer when checks are off; check runs in Rust off the UI thread; entry chunk +≤ 3 KB gz (dialog lazy).

## Success Criteria
- [x] Installing over a running Kelpie never fails on files in use and never touches daemons outside `$INSTDIR`.
- [x] A signed update installs from GitHub Releases; resumable agents resume; a bad signature never installs.
- [x] The release build has no override path (CI check).

## Risk Assessment
- Lost private key = no more updates for existing installs → offline backup by the user; signal: release job fails to sign.
- Daemon fails to stop within the timeout → install aborted with a message, nothing lost; offer "stop sessions and retry".
- NSIS `nsExec` or the hook macro not available in Tauri's bundled NSIS → fall back to `ExecWait` (brief console flash).
