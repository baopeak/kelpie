## Re-review blockers fixed
- **RB-1 Cancel.** Per-Finish state keyed by worktree (`finish_cancel(worktree)`, `finish_reset(worktree)`), no process-wide flag: `runFinish` resets it at the start and in `finally`, `finish_integrate` clears its key when it returns, so a cancelled or finished run never leaves it set for the next. Honoured at every boundary: after stopping sessions, after the re-list, around the WIP commit (a signing/commit wait ends with "cancelled"), before the merge, inside the merge/signing/checks (backend), before the CAS. Before the base moves Cancel = nothing changed (`Cancelled`, base/branch/worktree untouched). After the CAS (`moved` flag in Rust) a Cancel is never mapped to "nothing changed": the run skips only the removal, puts the branch back, and reports "merged into X; worktree and branch stay"; the dialog disables the button past the merge. Tests: Cancel for one worktree does not touch another's Finish, stops its own with refs unchanged and is cleared afterwards; a stale Cancel fails the WIP commit only until `finish_reset`; Cancel during a signer that never answers ends the wait with nothing changed; vitest for Cancel at each step, after the merge, and the reset calls.
- **RB-2 leftover check worktrees.** Before each check run, worktrees named `kelpie-finish-<pid>-*` directly in the temp folder whose pid is not alive (and not ours) get `unlink_shared` (links removed, never followed), `remove_dir_all`, `worktree prune`. Test: a stale worktree with a junction to `node_modules` is gone, the target survives, git's record is gone, a live process's folder is left alone.
- **RB-3** the check worktree gets the base's `copy:` / `link:` only when `configApproved` (setup section) holds; the dialog says when they are skipped.
- **RB-4 / RB-7** approvals are stored as content: `approvedSetups` holds the canonical text of setup/tabs/copy/link (no FNV hash), `approvedChecks` the exact list. New worktree pre-ticks only when both match; a changed check is marked "(new since you approved the checks)"; opening the dialog approves nothing. Old hash values never match: one re-approval. e2e: setup approved as it stands but checks changed -> unticked, marked, approved list unchanged; both approved -> ticked.
- **RB-5 / RB-6** `core.hooksPath=/dev/null` in `git_finish.rs` and the daemon's `checkpoints.rs`; the private folder, emptying and `missing` fallback are gone. A `read-tree` that fails to even start after the CAS takes the same undo path; "Cancelled" is only mapped before the CAS. Tests: repository hooks and a husky-style `core.hooksPath` folder do not run through a full Finish; the daemon's snapshot git calls carry `/dev/null` and ignore a repo `reference-transaction` hook.
- Not done (Lows): spawning checks suspended into the Job object; `checkpoint.drop` for a session that has no snapshot yet.

## Choices to know
- Hooks off for every Finish git call, including merge/squash/rebase commits (plumbing); signing on when the repository signs. Job object (not `taskkill`) kills check trees on Windows.
- Dirty main checkout still blocks (tracked changes) — moving the branch under it would leave a trap.
- A rebase refuses merge commits / a root commit.

## Not done / limits
- No "resume" state for a crash between branch deletion and removal (acceptable per the re-review: the worktree is detached at the tip and shows the detached-HEAD message).
- Cold summaries ~110-130 ms per worktree (20 cold = ~2.2 s, now on the 2-slot review pool so interactive git is not queued); cached refresh passes the 50 ms assertion (7.7-9.1 ms measured earlier).
- `ui_tour.py` and macOS not run (process-group kill and `Tree` on unix compiled only for Windows here); open-handle test is Windows only. Rust error strings stay English in the VI UI (existing pattern).
- Automation delivery mapping is in memory (a daemon restart mid-run drops it); auto-worktree only in the New session dialog.
