## 2. Data availability per protocol (what adapters can/can't give)

- Claude stream-json (already consumed): tool_use `input` (file_path, offset, limit, old_string, new_string, command, description, todos) -> items 1-4,18 need NO adapter change; `tool_result` -> output. Thinking duration: live `content_block_start/stop` timing (replay of log = bulk, durations lost; history jsonl has `timestamp`). Usage: assistant `message.usage` (input/cache_read/cache_creation tokens, `cache_creation.ephemeral_5m/1h_input_tokens` VERIFY) and `result.modelUsage[model].contextWindow` VERIFY. `control_request {subtype:"get_context_usage"}` is a real CLI request (extension uses it) - exact shape VERIFY with a probe. `rewind_code {userMessageId}` + file checkpointing env var VERIFY. Permission `deny` carries `message` (free text).
- Codex app-server: commandExecution (command, aggregatedOutput, durationMs on item VERIFY), fileChange (diff text), reasoning items (no duration), `turn.durationMs` already read (codex-adapter.ts:361). Token usage: `thread/tokenUsage/updated` with `modelContextWindow` VERIFY (not consumed today: grep tokenUsage = 0 hits).
- ACP (OMP): tool_call (kind, locations, rawInput, diff oldText/newText), plan entries, `usage_update {used,size}` only if agent implements the unstable method VERIFY. Thinking duration none.
- Timestamps: ChatController can stamp `Date.now()` in `upsert` when `!isReplaying`; replayed items have none (attachTerminal callback gives `(seq,data)` only, no time). Claude history items (mode-switch.ts:84-90 loadHistory) have `m.timestamp`.
- NOT provided by any protocol: `Run in background` (21), agent-map tokens/time for Codex/ACP, Codex/ACP rewind.

## 3. Prioritized gap list

Ranking = user-visible polish per effort, no protocol risk first. Effort S <=0.5d, M 1-2d, L 3d+.

### P1 - transcript density (the look the user likes). All data already in `ChatItem.input/output/diff`.

1. **Per-tool header renderer** (S). `Read file.py (lines 75-80)`, `Edit file.py - Removed 1 line`/`Added N lines`, `Bash <description or command>`, `Grep pattern`, basename + path in tooltip. Why: today the line is a raw full path with a bold tool name. Data: `input` present for Claude/ACP(rawInput); Codex Shell has `summary`=cmd, Edit has diff[] (count +/- lines). Files: new `app/src/chat/tool-header.ts` (pure fn item->{verb,target,meta}, unit-testable like layout.test.ts), `chat-pane.tsx` ToolCard head, `chat-model.ts` summarize stays as fallback. Adapter change none. i18n: verbs through t() in locales/vi/tools.json.
2. **Diff presentation** (M). Finished edits stay collapsed under a `Removed/Added N lines` header; expanded view = two-column red/green (old on left, new on right) using old/new strings; unified fallback for Codex `diff` text. Cap ~200px with gradient + `Show more`/`Show less`. Data: Claude old_string/new_string available in `input` (currently flattened to `-`/`+` text in diffFor, so side-by-side requires either parsing back or adding `diff.old/new` fields to ChatItem diff type); ACP oldText/newText available; Codex unified only -> render unified. No line numbers from Claude Edit (ext reads file; Kelpie could skip). Files: chat-model.ts (diff type `{path,text,old?,new?}`), claude-adapter.ts diffFor, acp-adapter.ts toolContent, chat-pane.tsx, styles.css (`.diff-line` 516-517).
3. **IN/OUT body rows** (S). Labeled `IN` (pretty JSON; for Bash show command) and `OUT`, each clamped ~10 lines with `Show more`, copy button; replaces single pre (chat-pane.tsx:85-90). Data present. Files: chat-pane.tsx, styles.css.

## 4. Trade-off / risk summary

- P1 items 1-5 are render-only over existing data: lowest risk, highest visible gain. Keep logic in pure helper modules with vitest (vitest.config.ts exists) because chat-pane.tsx is already dense.
- Grouping (4) changes the DOM shape; check interplay with `content-visibility: auto` on `.chat-inner > *` (styles.css:530), the stick-to-bottom effect (chat-pane.tsx:126), and `RENDER_WINDOW` slicing (slice by items, group afterwards, or a group may be cut mid-run).
- Sticky prompt (7) must be per-turn container or it stacks.
- Context ring (10) depends on unverified wire fields in 3 protocols; do a 30-minute probe per agent before committing; never fake a window size.
- Do not copy: Monaco diff editor (heavy; a two-column div diff is enough), engine/"rowAsks" paint scheduler (over-engineered; Kelpie windowing is adequate).
- Adoption risk of copying UX from an extension that changes weekly (2.1.304): mimic structure, not exact strings; strings go through t() / vi locale.
