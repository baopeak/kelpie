# Sub-session vs subagent in Claude Code (CLI + desktop), 2026-11-07

Tags: [official] = Anthropic/vendor docs; [3p] = third party; [unv] = unverified/inferred.
Short names: CC = code.claude.com/docs/en. SA = /sub-agents, AV = /agent-view, AT = /agent-teams, XS = /cross-session-messaging, D = /desktop, C = /costs, P = /agents.

## 0. Terminology (correct this first)
- "Sub-session" is NOT a defined term in official docs [official, absence confirmed across SA/AV/AT/XS/D/P]. Docs say: *subagent*, *background session* (AV), *teammate* (AT), *fork*, *session* (D), and in D: Start chip "runs the task in a new session ... sidebar lists the started session under the current session" (https://code.claude.com/docs/en/desktop) [official]. My fetch tool's phrase "which is how sub-sessions are placed" was a summarizer gloss, not verified doc text [unv].
- "Nested sessions" = marketing/press name for the 2026-10-14 desktop update: child sessions Claude opens "when asked to run several tasks in parallel", linked hierarchically, report result back to parent (https://pasqualepillitteri.it/en/news/24032/claude-code-desktop-nested-sessions-environments, citing ClaudeDevs X posts 2026-10-14) [3p, secondary of official posts]. Same article does NOT compare to subagents and gives no cost numbers. Mejba post says each child = full session with own history/context/permission mode (https://www.mejba.me/blog/claude-code-desktop-nested-sessions) [3p].
- Working definition: **subagent** = worker inside ONE session's Agent tool, own context, returns summary. **Sub-session** = a full, separate Claude Code session (own transcript, own permission mode, user can open it) that is merely *linked* to a parent in the UI. Docs say it exactly so: "Subagents work within a single session. To run many independent sessions in parallel ... background agents" (SA) [official]; "In every approach the workers are Claude sessions" (P) [official].
- Doc trap: `/fork` vs `/subtask`. A *forked subagent* (`/subtask`) inherits full context but stays a subagent. `/fork` copies the whole session into a new *background session* (with agent view on) (P, SA) [official].

Pattern: Claude Code, Codex, Gemini, Cursor all keep "subagent" = in-session delegate with summary-only return; Orca and agent-deck (external orchestrators) make "child" a real terminal/CLI session with parent linkage and inbox/nudge notifications. Claude desktop's "nested sessions" moves CC toward the second model.

## 4. When to use which
Official [P, SA, AT]:
- Subagent: side task would flood main context (search, logs); self-contained, wants summary; tool restriction. Not for frequent back-and-forth or shared-context phases.
- Background session: independent tasks you hand off, check back later; user is the only recipient of results.
- Agent team: workers must talk to each other, Claude assigns/supervises; avoid for sequential/same-file work.
- Worktree: any parallel writers on same repo.
Practitioner [3p]: self-contained ticket ending in commit/PR -> own session with worktree; short read-mostly step -> subagent (https://amux.io/guides/claude-code-subagents/). "When in doubt don't spawn" (AgentKit). Bound fan-out (aident.ai) [3p].

## 5. Takeaways for Kelpie (analyst view)
1. Treat "sub-session" as a UI relationship (parent link) over a normal full session; do not model it as a subagent. Evidence: D, AV, P all separate them.
2. Key discriminators: own process + survives parent + user can chat directly + own permission mode = session. Own context but parent-owned, summary-only return = subagent.
3. Cost: sessions multiply quota linearly and each reloads startup context; subagents add overhead too. Only hard official multiplier is ~7x for plan-mode teammates.
4. Parent linkage in other tools (agent-deck `--parent` + status nudges; Orca coordinator inbox) is the proven UX pattern; CC offers messaging + `notify_when_idle` (main conversation only, same machine only, 12 h expiry) [official XS].
5. Permissions are per-session and messages are never consent; a Kelpie parent must not auto-approve a child's prompts.
6. Isolation default differs: agent-view dispatched = worktree; desktop toggle off; subagents shared checkout.
