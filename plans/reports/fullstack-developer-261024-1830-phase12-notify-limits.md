### What was built
- **One event source (daemon `notify.rs`).** `Notifier::observe` classifies every changed session (`waiting` / `finished` / `error`, parity with the old `maybeNotify`), plus `automation`, `approval` (run task waits) and `cost`. App consumes `notify.event` for inbox + desktop notification (`store.ts` `onNotifyEvent`, wording in `lib/notify-events.ts`); against a daemon < API 12 the old window-side rule stays (`store.legacyNotify()`), and `ui.focus`, banner, cost report, switch-account are all gated on API 12.
- **`ui.focus {focused, visible[]}`** (per connection, dropped on disconnect): a status event for a session a focused window shows is neither broadcast nor sent to the phone, so desktop and push agree by construction. `lib/notify-sync.ts` reports it (150 ms debounce, deduped, re-sent after reconnect).
- **Channels** (Settings -> Notifications -> "Off this computer", lazy chunk `push-settings.tsx`): ntfy (server, random 128-bit topic created when first switched on, optional token, Show/Copy/New topic), Telegram (bot token + chat id + Send a test), webhook (JSON). ureq (ring TLS), no redirects, 10 s timeout, one retry after 3 s on transient errors. Errors say what failed ("HTTP 500", "timed out"), never where. Filters: 6 event switches, turn >= N s (default 30), away-only (window not focused or OS idle >= 5 min, Windows), 1 message / session / 30 s. Screen text off by default with a warning; redacted; 14 lines / 1000 chars. Names/titles from the terminal are forced to one control-free line (200 chars) then redacted.
- **Deep link** `<phone url>/#s=<session id>` only while phone access is on; no code/token ever; phone page (`mobile/app.js`) opens that session after login and strips the fragment.
- **Continue at reset.** Claude `StopFailure` with `error: rate_limit` (field verified in Claude Code docs) sets `SessionInfo.limited`; other agents have no structured signal, so no banner for them. Banner in `pane-view` (lazy `limit-banner.tsx`): Continue at reset (meter `resets_at` of the session's own account, else a time the user types and confirms), Switch account..., Hand off to.... `session.schedule_continue {handle, at, source: meter|confirmed}` keeps `{session, generation, agent_session_id}` in the daemon (`scheduled_input.rs`); at fire `Session::continue_if_limited` checks under the session lock: same generation, same conversation, still failed+limited, idle, no input since the failure; then types `continue` (+ separate Enter). Else cancelled + `scheduled.updated {reason}` -> inbox note.
- **Switch account.** `account_transcript` (Rust) copies Claude `projects/<folder>/<id>.jsonl` (+ sub-agents) / Codex dated rollout into the target home (never overwrites; refuses with reason before anything stops: other agent, same account, home not made by Kelpie, target not signed in, different conversation already under that id, > 1 GB). Then `session.set_env_restart` (stopped terminal session, only the account variable, existing absolute folder; reverted if restart fails).
- Docs: `docs/architecture.md` (new "Notifications and limit actions", RPC/event lists, accounts row, measured), `docs/user-guide.md`, `README.md`.

### Secrets: how test isolation is guaranteed
- Keys: `notify-ntfy-topic`, `notify-ntfy-token`, `notify-telegram-token`, `notify-webhook-url` through `kelpie_proto::secret_*`, whose service is `Kelpie (<KELPIE_ENDPOINT>)` whenever the endpoint is set. The installed app has no endpoint -> service plain `Kelpie`; a dev/test daemon can never read or write its entries (legacy fallback service is endpoint-scoped too).
- cargo tests: the notifier takes a `SecretStore`; every test uses an in-memory store (`Memory`, `#[cfg(test)]`); only `main.rs` builds `Daemon::new` with the real keyring. No cargo test touches the credential store.
- `notify.py`: sets `KELPIE_ENDPOINT=kelpie-notify-<pid>` (asserted prefix), `KELPIE_DATA_DIR` scratch, `KELPIE_E2E` in its own `os.environ` before any daemon call; `KELPIE_ALLOW_REAL_DAEMON` popped. It lists credential-store *target names* (never values) before/after: new entries must all contain its endpoint name (4 observed, `notify-*.Kelpie (kelpie-notify-<pid>)`), `notify.clear` removes them, and after cleanup the set equals the baseline (checked in every run). Verified again by hand after the last run: no `kelpie-notify` / `notify-ntfy` entry left. The real app (pid 7200) and daemon (pid 14260) were never connected to or stopped.
- No secret / topic / token / sink address in any file of the data folder or in the daemon's `RUST_LOG=debug` log (asserted).
- No real network: local HTTP sink on 127.0.0.1 stands in for ntfy, webhook and Telegram. Telegram base is overridable only when `KELPIE_E2E` is set AND the address is loopback http (`telegram_base_for`, unit-tested with 7 hostile inputs). Request addresses are never logged.

### Review round (code-reviewer-261024-1930): all findings addressed
- **H1** `Activity` now records when the failed turn began (`turn_started`, first working report after idle) and a turn counter. A timer fires only if nothing was typed since that moment (the Enter that sent the prompt is the last keystroke allowed), so a half-typed draft blocks it; the timer also stores the turn and is void if another began. **Forged limit report:** a refused timer marks the limit dead for that run of the agent (`limit_dead`), so a program calling `hook.report StopFailure rate_limit` cannot bring the banner or timer back (e2e: `typed` session, forged report, schedule refused). Residual: a program that forges a whole fresh turn (`UserPromptSubmit` then a failure) before the timer fires is a lie about agent state the daemon cannot tell from a real one; the turn check voids the timer then. I did not require the session token on the hook path: some agents strip token variables from hooks, which would kill the feature there.
- **H2** `Notifier::looking_at` is false when the computer is idle for 5 min (`GetLastInputInfo`, Windows), so the event reaches the inbox and the phone; desktop and push still agree. Threshold is the fixed 5 min (no setting). Unit test with an injected idle source; e2e covers it live (this machine was idle during most runs and the script asserts both branches).
- **H3** Timers are written to `<data>/scheduled.json` (via `persist::write_atomic`). No process survives its daemon, so none can pass its guard after a restart: at start they are loaded as **lost** and returned once by `session.scheduled` (`{timers, lost}`); the app turns each into an inbox note ("the session daemon restarted") and **replaces** its list (`reconcile`, vitest-covered: a vanished timer is gone, lost ones noted once). Closing/restarting a session cancels its timer at once with its own note (L3). e2e restarts the daemon with a pending timer and checks file, lost report, once.
- **H4** Switching back: a target file that is the byte-prefix of the source (older copy, also each sub-agent file) is replaced through `.part` + rename; a longer/newer target is refused ("newer copy"), a diverging one is "different conversation". Round-trip test A to B, append, B to A. Also (L4) more than 2000 files is refused instead of copied in part.
