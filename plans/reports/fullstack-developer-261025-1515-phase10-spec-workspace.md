## What was built
- **Plan tab** (right panel, lazy chunk): `plans/*/plan.md` + `phase-*.md`, `specs/**`, `.kiro/specs/**`, `docs/plans/**` as groups → files (phases) → tasks with checkbox state, nesting, progress. Unfinished groups open and first; a file without boxes lists its list items; too-large / non-UTF-8 files are listed with a note. Local **and remote** projects.
- **Parsing** (`spec-index.ts`): marked's block lexer for the file, inline tokens only for headings and each task's first block. Line numbers from token raw text, each checked against the checkbox pattern on its line (unconfirmed → shown, not tickable). Code blocks / html comments / tables never count. CRLF / CR / BOM handled. Heading and task text scrubbed of control, bidi and invisible characters.
- **Live progress**: existing `fs-changed` events only while the tab is mounted, only for the four roots, 300 ms debounce, reconciling just the named folders. `stats` counters exposed to the e2e. A host (remote project) has no watcher: refresh button, and a refused tick re-reads by itself.
- **Manual tick** (`index.tick`): file and every parent re-checked as plain entries (no symlink / junction), fresh read, mtime + content digest + line must equal what was parsed, then `fs_write_file` with that mtime as `expectedMtime`; exactly one character changes; strict UTF-8 so write-back is byte-exact. Mismatch → nothing written, folder re-read, toast.
- **Run with…** per task: agent × `here` / `worktree` / **host**. One-task Run via `createSpecRun`; task id `spec-<hash(path,text,nth)>` so the row finds its run (`runOfSpecTask`, no `task_ref` store); chip shows status and opens the run. Prompt = scrubbed instructions + the file via `expandMentions` for the agent's kind (`@path` or fenced content), all through `redact`; heading / task text appended after the expansion so it cannot become a mention. Worktree: `materialize` only from an approved `.kelpie.yaml`; uncommitted spec file flagged.
- **Host mode (new, daemon API 16)**:
  - Daemon: `runs::TaskHost { dest, port, config, path }` as `Task.host` / `NewTask.host`. `build_run` validates (destination = letters, digits, `._@:%[]-`, not starting with `-`, ≤ 255; port ≠ 0; absolute folder with no control characters; `config` not an option / not empty) and **refuses a worktree on a host** ("a worktree is made on this computer…"). `start_task` passes it to the ordinary session path as `remote` + `cwd`, i.e. `agents::build_remote_launch` (ssh -t, login shell, never tmux: see the review round) — the same as a pane on that host. The task prompt of a host task omits the report command (a program of this computer); the task ends with its ssh session (or Mark done / idle).
  - Auth: `auth::scope_session_params("run.create")` **refuses** (does not drop — the task would run here) any task that names a host when the caller is a session; claimed sessions cannot call `run.create` at all (existing table, now tested).
  - App: Run with… offers `On <host>` for each saved host linked to a local project (folder = the one linked there, via `resolveRunOn`: checks the host, handles new host keys, needs the project's folder; root-Yolo confirm via `confirmRootStart`), and for a **remote project** `On <its host>` (its own folder). No worktree option there. The host's askpass env (`ssh_session_env`) and the generated ssh config go with the task, as for any remote session. Offered only when `daemonApi() >= 16`; `createSpecRun` also throws before sending on an older daemon (it would ignore the field and run the task here). Runs page shows `on <host>`.
  - Remote projects get the Plan tab (list / read / tick / create over ssh through the existing `fs_*` commands, which speak ssh for `ssh://` roots; times are whole seconds, content digest decides). Remote Windows hosts not specially treated.
- **New spec**: palette "New Spec…" / panel button → `specs/<slug>/requirements.md`, `design.md`, `tasks.md`; slug ASCII ≤ 48, no device names; refuses a link / file at `specs/` or `specs/<slug>` and any existing file; works on a host too.
- Tab bar: `.panel-tabs` scrolls (wheel; active tab scrolled into view).

## Final check round (F1-F3 and lows): all addressed

- **F1 (blocking)** `remote.rs` `WRITE_SCRIPT`: the temporary file is `mktemp "$f.kelpie-tmp.XXXXXX"` in the target's own folder: created exclusively (a name that already exists, a planted link included, is never opened) and with mode 0600; the mode is then set to the file's own (or the umask default for a new file) just before the rename.
