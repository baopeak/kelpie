## Review fixes (this round)
**High**
1. **`~/.claude.json` races.** `apply` is serialised and, for Claude's file, takes Claude's own lock (`<file>.lock` directory, `mkdir`, stale after 10 s, waits up to 5 s, never touches another program's live lock). Under the lock: compare with the previewed text right before the swap (refuse "changed since the preview", no backup written), backup, write, verify. Verify now tells apart *my write is broken* (disk holds what I wrote but it no longer parses) from *someone wrote after me* (disk differs): in the first case the file (and earlier files of the edit) are put back, but only if they still hold exactly what Kelpie wrote; in the second the file is left as the other program saved it, earlier files are put back, and the error says so ("was changed by another program right after Kelpie wrote it. Check that your change is still there ... Left as another program saved it: path (backup id)"). Any non-success returns an error, so the UI never shows "Saved" for a write that did not stick. Tests: lock held by another program (refused, lock untouched, nothing written), stale lock taken over, lock held during compare/write and gone after, other files take no lock, foreign write before the swap, foreign write after (single file and multi-file with rollback of the earlier file), broken own write with and without a foreign save after it. e2e covers the lock.
2. **Project paths that leave the repo.** `confine()` (canonicalised, deepest existing ancestor, links and junctions) guards every project-scope path: MCP files, `.claude/settings.local.json`, all four unify paths (`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `.gemini/settings.json`) before anything is read for writing, and Restore of a project file. Refusal names the real target ("... resolves outside the project: <real path>"); the overview lists the file with that error instead of reading it; the instruction list does not read an outside file. A link that stays inside works and the diff shows where it leads (`real_path`). Tests (junction on Windows, symlink on unix): `.cursor`, `.gemini`, `.claude` dirs out (add, copy, toggle, unify refused, outside folder unchanged, error listed); unix-only: file symlinks on `CLAUDE.md`/`AGENTS.md`/`GEMINI.md`/`.mcp.json`/`opencode.json` (real target named, no content copied into the repo). e2e: a junction `.gemini` -> outside folder: listing error, copy refused, one-file-for-all refused, outside untouched.
3. **`CLAUDE.md -> AGENTS.md`.** Same file (either direction) or identical text: nothing written to them, accurate message (`already_linked` / `already_same_text`), Gemini step still runs; a stray `@AGENTS.md` line is stripped from text moved into AGENTS.md; the "imports AGENTS.md" status counts a link. Tests: unix symlink both directions; hard link / identical text and stray import on all platforms.
4. **Untrusted project -> user copy.** The preview (and so the confirmation) lists argv per element (quoted), url, working folder, every env and header entry as the repository wrote it (unmasked; a reference to the user's own variable is named "reads your variable X", never expanded), whether each will be written, and every relative path that was made absolute. Rust (`for_destination(..., untrusted)`, `pin_to_project`) enforces: nothing of the project's env/headers is carried unless `include_env` is ticked and the destination is the user's file; no reference to the user's same-named variables is invented for project sources; a relative command, relative path arguments (`./x`, `../x`, `--opt=./x`, existing in-repo paths) and a relative working folder are resolved to absolute in-repo paths (refused when they would leave the project, or when the destination agent cannot set a working folder); `apply` still refuses without `confirm_untrusted`. Tests: contents of the untrusted block, not-ticked vs ticked, cwd, `../` refusal, bare program names left to PATH. e2e: absolute path, env list, "reads your variable", ticked opt-in writes exactly the listed values to Codex.

The test junction/lock live in the fixture and are removed.
